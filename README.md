# LexChain 律链

LexChain 面向遇到劳动争议的劳动者，默认提供「工人求助」流程：选择问题、填写事实、核对证据、查看初步意见。优先支持欠薪月份整理与工资差额小计，保留专业事实面板和可审计的规则推演。

## GitHub Pages

公开页面：`https://nininininini979-tech.github.io/lexchain/`

Pages 版本在浏览器内加载规则和法律目录并计算，不上传案件内容或文件，不调用模型 API。求助模式只使用用户明确回答的选项和金额，不从自由描述猜测事实。空白金额保持未知；不完整月份不计入小计；重复月份会拦截。科研案件和科研工作区支持显式保存到当前浏览器，以及 JSON 导出和导入；普通求助草稿刷新后可能清空。

工人求助与专业审阅共享案件事实。专业面板修正后，返回求助模式会重新计算；有争议或未知的事实仍需人工核对。公开版已取消容易误判的关键词抽取，请使用事实面板；本地专业模式仍支持已配置的 DeepSeek/Ollama，点击文本分析前页面会说明发送范围。

意见区区分已匹配法条与条件未确认的相关条文，展示证据缺口、可能的其他解释与求助路径。适用范围为中国大陆劳动争议，当前规则库 v0.5.1（34 条规则）；地方规定、最新裁审口径及法规整体有效性尚未经人工法律复核。工伤及其他争议仅作材料整理和人工转介。

本版只估算工资差额，不自动计算加班费、二倍工资差额、经济补偿、赔偿金或工伤赔付，不保证案件结果。金额还需核对税前/税后口径、合法代扣、到账及应付日期。

## 科研工作台

- [联合推导与科研工作台](https://nininininini979-tech.github.io/lexchain/workbench.html)：规则依赖、冲突与优先依据、更新对照、整链证书核验、三组实验与复现、证据标注、法律版本管理和原文字面检索。
- [KD 道义模态研究](https://nininininini979-tech.github.io/lexchain/modal.html)。
- [条件义务与优先序研究](https://nininininini979-tech.github.io/lexchain/conditional.html)。

工作台不需要购买服务器。使用现代浏览器通过 HTTPS 打开，填写工作区名称及研究者代号后新建工作区；首次体验可选择“采用合成研究示例”，再运行联合分析、核验和实验。计算通过浏览器 Worker 执行。

保存仅限当前浏览器，不提供跨设备同步或多人账户认证。清理站点数据、隐私浏览模式或存储配额不足都可能影响保存，请使用“导出完整工作区”备份；换设备可导入 JSON。标注者和审核者代号属于研究记录中的声明，不是已认证身份。

当前 34 个法律版本均待人工法律审核，适用结论标记为 `REVIEW_REQUIRED`。自定义规则及受其影响的结论仅供研究。整链核验确认输入与计算一致，不证明材料真实、法条适用正确或法院会作出相同结论。随附合成数据用于功能演示，不能当作法律准确率或论文实证结果。

## 发布与版本管理

本仓库只发布 `docs/` 静态产物和说明，不包含本地后端、个人案件、API Key 或浏览器保存的数据。GitHub Pages 从 `main` 分支的 `/docs` 发布；更新使用独立分支和 Pull Request，合并后检查 Pages 构建及线上页面。

网页来源为本地 2026-11-12 `review.1` 复查版本，通过 `node scripts/build-pages.js` 生成；构建源保留在本地开发项目。此次发布同步工作台依赖的模态、条件义务和案件集成模块，并保留原求助入口。后续更新应从开发项目重新构建，避免手工修改生成文件后又被覆盖。

发布验证同时修复求助表单误读隐藏专业面板的情况：只读取当前求助表单，空白数字不再被写成布尔值。包含该回归用例的本地测试共 281 项通过，49 个既有样例的 57 项规则预期全部通过。

浏览器保存的数据不进入 Git。回退网页时使用对应发布提交的 `git revert`，再检查 GitHub Pages 发布结果；不要强推覆盖主分支历史。

> 本工具输出仅供法律风险分析参考，不构成正式法律意见。
